Planning & Distribution
Compute per-topic targets from AICPA Blueprint weights. 5,000 questions per section, 30K total.

What happens

  • Blueprint structure (6 sections, areas, groups, topics) defines the target distribution
  • Each topic gets a proportional question count based on exam weight
  • Difficulty split: 30% easy / 50% medium / 20% hard
  • Bloom's targets: L1 20-25% / L2 35% / L3 20-30% / L4 15%

Selection strategy

  • 30 questions per batch (default), 10 for verification

3
Scaffold Generation
Create SQL migration template with TODO placeholders for Claude to fill.

Scaffold types

  • INSERT (generate mode): 30 new question tuples with TODO placeholders
  • UPDATE (citation/difficulty/blooms/moderate): rewrite existing questions
  • UPDATE fix (verify mode): targeted corrections for failed questions

Each question slot includes

  • Section ID, topic, difficulty target, Bloom's level target
  • TODO placeholders for: stem, choices JSON, correct_index, explanation
  • Bloom's-to-difficulty alignment (L1 prefers easy, L4 prefers hard)

4
AI Fill-In (Headless Claude)
Each batch runs in a fresh Claude context. Fills all TODOs with substantive CPA exam content.

How it works

  • Orchestrator (scripts/orchestrate.ps1) runs claude --print per batch
  • Fresh context window per batch (prevents overflow on 100+ batch runs)
  • Claude receives: scaffold file, lesson content, frameworks, existing stems
  • ~3-5 minutes per batch

Content requirements

  • Stems: L1 = 10-20 words, L2+ = 20-60 words with scenario (entity, amounts, dates)
  • Choices: 4 parallel-grammar options, no "all/none of above"
  • Explanation: 50-100 words. Cite standard, explain correct, contrast wrong answer
  • Variety: Each question tests a different concept

Deduplication
Trigram-based Jaccard similarity catches near-duplicates before they ship. 85%+ = blocked, 70%+ = warned.

How it works

  • Compares new stems against all existing stems in the section
  • Uses both raw and normalized trigrams (handles case/punctuation variance)
  • 85%+ similarity = likely duplicate (ERROR, blocks commit)
  • 70-84% similarity = near duplicate (WARN, max 3 allowed)
  • Post-generation cleanup deleted 6,244 duplicates + 90 TODO leftovers

Correctness Verification
Claude-as-reviewer checks substantive accuracy. Classifies questions, checks math, citations, logic.

Question classification

  • Calculation — contains $, %, "calculate", "determine amount"
  • Citation — references specific standard
  • Scenario — "most likely", "best approach", L3/L4
  • Conceptual — pure knowledge-based

Issue types checked

  • wrong_key — answer key doesn't match correct choice
  • arithmetic_error — calculation produces wrong number
  • citation_error — standard misattributed
  • distractor_also_correct — multiple valid answers
  • explanation_mismatch — contradicts stem/choices
  • logical_error — impossible scenario

Verdicts

  • pass — no critical issues
  • fail — critical issues, requires fix migration
  • review — uncertain, needs human inspection
